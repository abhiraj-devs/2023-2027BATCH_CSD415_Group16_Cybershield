=================================================================================================================================================
DETAILED TECHNICAL METHODOLOGIES EMPLOYED IN CYBERSHIELD AI
=================================================================================================================================================

1. EXPLAINABLE AI (XAI) PHISHING & URL ANALYSIS METHODOLOGY (M1)
----------------------------------------------------------------
- Syntactic & Structural Heuristics:
  * Analyzes URL structure for suspicious top-level domains (e.g., .xyz, .top, .tk, .click), raw IP hosts, and non-standard ports.
  * Measures subdomain nesting depth: multi-level nested subdomains mimicking corporate brands trigger risk score multipliers.
  * Calculates Shannon Entropy across the URL string: high entropy indicates DGA (Domain Generation Algorithms) or obfuscated redirects.
- Explainable AI Reasoning (Google Gemini):
  * Instead of returning a raw, uninterpretable probability, the feature set is passed to Gemini (@google/genai) on the backend.
  * Gemini evaluates deceptive brand keywords, urgency triggers, and spoofed authentication paths, outputting a clear, human-readable
    explanation describing *why* the URL is dangerous, empowering analysts to make informed decisions.
- Defensive Fallback:
  * If upstream AI services experience rate limits or network latency, the system seamlessly transitions to a deterministic heuristic
    scoring model to guarantee 100% uptime.

2. ZERO-KNOWLEDGE CLIENT-SIDE MALWARE FORENSICS METHODOLOGY (M2)
----------------------------------------------------------------
- Client-Side Cryptographic Fingerprinting:
  * Eliminates the risk, liability, and bandwidth overhead of uploading untrusted binary files or private documents to the cloud.
  * Uses the browser's native `crypto.subtle` API to compute the SHA-256 cryptographic digest directly in memory on the client machine.
- Cloud Reputation Consensus:
  * Only the 64-character hexadecimal SHA-256 hash is transmitted to the backend.
  * The backend queries VirusTotal API across 70+ commercial antivirus engines (Kaspersky, CrowdStrike, Microsoft, Sophos, etc.).
  * Evaluates PE header metadata, malicious signature flags, and suspicious file extension camouflage (e.g., invoice.pdf.exe).

3. REAL-TIME NETWORK TELEMETRY & FLOW ANOMALY DETECTION METHODOLOGY (M3)
------------------------------------------------------------------------
- 5-Tuple Connection Flow Inspection:
  * Ingests network flow metadata containing Source IP, Destination IP, Source/Destination Ports, Protocol (HTTPS, HTTP, DNS, SSH),
    transfer volume (bytes), and transmission speed (Mbps).
- Multi-Vector Anomaly Scoring (0-100):
  * Port/Protocol Discordance: Detects unusual protocols operating over standard ports (e.g., SSH or tunneling over 443/53).
  * Exfiltration Bursts: Flags sudden spikes in outbound throughput compared to baseline averages.
  * Periodic Beaconing: Identifies rhythmic outbound heartbeats typical of Command and Control (C2) agent communication.
- Live Telemetry Streaming:
  * Frontend employs an asynchronous 5-second polling loop against `/api/network/events` and `/api/network/summary` to maintain
    real-time SOC dashboards with zero page flicker.

4. THREAT INTELLIGENCE AGGREGATION & IN-MEMORY SEARCH METHODOLOGY (M4)
---------------------------------------------------------------------
- Indicator Normalization:
  * Consolidates heterogeneous threat feeds (PhishTank, VirusTotal, and CVE feeds) into a unified schema:
    Category, Severity, Indicators (IPs, URLs, Hashes), Target Sectors, and Detailed Countermeasures.
- In-Memory High-Speed Search:
  * Caches normalized feeds client-side to provide instantaneous, zero-latency multi-field substring filtering across IoCs,
    descriptions, and threat signatures as analysts type.

5. VULNERABILITY ASSESSMENT & EXPOSURE SCANNING METHODOLOGY (M5)
----------------------------------------------------------------
- Attack Surface Discovery:
  * Inspects target IP/domains for critical open ports (HTTP, HTTPS, SSH, FTP, RDP, SMB, MySQL).
  * Evaluates service banners for outdated or unpatched daemon versions.
- Defensive Security Header Audit:
  * Queries HTTP response headers to verify compliance with modern web security baselines:
    Content-Security-Policy (CSP), Strict-Transport-Security (HSTS), X-Frame-Options, and X-Content-Type-Options.
  * Generates an overall hygiene score with remediation guidance.

6. AUTOMATED SOAR INCIDENT RESPONSE & WEBHOOK ORCHESTRATION METHODOLOGY (M6)
----------------------------------------------------------------------------
- Immediate Event Dispatch:
  * When a scan detects high-risk threats (Risk Score > 75 or verified malware detections), the backend triggers asynchronous webhooks.
- Multi-Platform Enterprise Integration:
  * Supports Discord Webhook embeds (with dynamic color-coded severity banners) and Slack Incoming Webhooks (Block Kit JSON).
  * Reduces Mean Time to Detect (MTTD) and Mean Time to Respond (MTTR) by delivering actionable alerts to SOC chat channels in under 2 seconds.

7. ROLE-BASED ACCESS CONTROL (RBAC) & IDENTITY GOVERNANCE METHODOLOGY (M7)
--------------------------------------------------------------------------
- Passwordless Ephemeral OTP Authentication:
  * Generates cryptographically secure 6-digit one-time passcodes with a 10-minute time-to-live (TTL) and automatic memory eviction.
  * Prevents credential stuffing, password reuse, and database credential breaches.
- Deterministic Role Governance:
  * Differentiates privileges between Super-Administrators (full access to webhook configuration, raw audit logs, and global telemetry)
    and Security Analysts (scan execution, report generation, and personal history).

8. FORENSIC AUDIT LOGGING & DATA PORTABILITY METHODOLOGY (M8)
-------------------------------------------------------------
- Cloud State Persistence:
  * Scans, threat alerts, and telemetry anomalies are recorded in Google Firebase Firestore with immutable UTC timestamps.
- Forensic CSV Export:
  * Implements in-browser dynamic Blob serialization to export consolidated CSV reports containing forensic metadata, network flows,
    and threat indicators for compliance audits and incident documentation.

9. CROWDSOURCED THREAT VERIFICATION METHODOLOGY (M9)
---------------------------------------------------
- Collaborative Analyst Triage:
  * Enables security analysts to validate, upvote, or flag zero-day threat submissions within the platform.
  * Closes the gap between automated detection models and newly emerging campaigns through crowd-verified consensus.
